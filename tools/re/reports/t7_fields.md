## Independent measures

- Registration: each field is one Scr_AddClassField call made by the engine's own registration code under emulation (class, canon, offset as the VM stores them).
- Tables: per (VM, class, offset group), entries at one constant stride, offset low bits = entry index, and the entry after the last has canon 0 (every table above: see the log).
- Read-only: by the field's own setter run alone, else by the VM's object-field setter dispatch (Scr_SetObjectField, entity 0): setter run 336, dispatch run 262, no setter: generic field write (dispatch not reached) 108, dispatch run (value read, no read-only error) 18.
- Both measures decided and agree on 59 fields; disagree on 0. The dispatch reaches the sub-kind setters (sentient, actor, player, vehicle) only on a live entity, so on entity 0 it stops first; the CSC dispatch reads the value before it looks the field up.
- Vehicle nodes carry a writable byte in the entry: it agrees with the dispatch on 12/12.

What this says about the rule: it is quiet (a few dozen names over the whole mod-tools tree) but most hits are not typos. To make it usable: (1) expand macros before collecting assignments (`DEFAULT(x, v)` assigns `x`); (2) do not flag fields read off objects that come from asset getters (script bundles, `settings`), which the workspace never assigns; (3) keep distance 1 for short names (the distance-2 hits on 2-4 letter names, `_on`/`font`, `org`/`dmg`, are noise); (4) report it as a hint, not a warning, when the workspace is partial (the mod tools ship only part of the game's scripts).

## Open issues

- Type codes with one or two matched names (1, 11, 15, 17) have weak labels; code 1 is labelled F_VECTOR from a single field while code 6 is the usual vector type.
- The read-only verdict of 108 fields with no setter rests on the generic field write path (the dispatch does not reach sub-kind fields on entity 0). Making the dispatch reach them needs a live entity with its sentient/actor/client/vehicle pointers set.
- The CSC registration (0xe3c6e0) faults in the tail call that follows its last registration (the weapon table); every table it registers is complete by the terminator check.
- The official Vehicle sheet also lists 11 vehicle-node fields; the executable registers them on class 3, not on vehicle entities.
- The dump is the current Steam build (PE timestamp above); the field list is from 2016.

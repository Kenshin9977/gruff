# E0301 decompiler-name

## What it does

Reports a name in decompiler output that no tokenizer can read as one name: a hash lookup resolved to text with spaces or `:` (`init heli sounds max_accuracy = x;`). It replaces the cascade of syntax errors such a line would otherwise cause.

## Why

The file does not parse as GSC and cannot be fixed by the parser: the decompiler's name table is wrong. `gruff check` reports it and skips the builtin (`B`) and loop (`L`) rules on the file, whose tree is a guess.

## Example

```gsc
self.init heli sounds = 1;   // E0301
```

Fix the name in the decompiler's table, or ignore the code on a decompiled corpus.

## How to suppress

On the line (or on its own line just above it):

```gsc
...  // gsc: ignore[E0301]
```

For a whole file, anywhere in it: `// gsc: ignore-file[E0301]`. In `gruff.toml`:
`ignore = ["E0301"]`, or `[check.per-file-ignores]` with `"pattern" = ["E0301"]`.

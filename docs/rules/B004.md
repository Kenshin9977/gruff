# B004 bare-call-other-namespace

## What it does

Reports a bare call (`foo()`, `ent foo()`, `thread foo()`) or a bare function pointer (`&foo`) that nothing in the caller's namespace defines and no builtin matches, while a function of that name exists in another namespace, typically in a `#using`'d file. When every such function is in one namespace the message names it and an **unsafe** fix qualifies the call (`util::foo()`).

Only games whose profile sets `bare_call_resolution = "namespace-first"` are checked: Black Ops III (T7, measured in the game's VM), Black Ops 4 (T8: the retail bytecode and acts' reimplementation of its linker), and, carried from it, T9, T10 and T11. The rule needs the game's complete builtin catalogue (`gruff-data/builtins/<game>.toml`); it is silent without one.

Calls in `/# #/` dev blocks are not checked: the retail catalogues lack some dev-only builtins (BO4's `destroy`), and the game links a dev block's calls only when dev blocks are on. Decompiled files are not checked either. acts writes a call bare whenever its import names the script's own namespace, `sys` or the empty namespace, so a bare call in its output may have been `ns::f()` in the source: in the Cold War scripts, `function_c07eafa2()` of `killstreaks/mp/ac130.csc` is an import of `ac130::function_c07eafa2` without the get-call flag, a qualified call.

## Why

In these games the compiler turns every bare name into an import of `<current namespace>::foo`. When the script loads, the game's linker looks for a script function of that namespace, then (calls and `&foo`, not threads) for a builtin, and stops there: `#using` makes the other file's functions available to qualified calls, not to bare ones. The game refuses to load the script (`Unresolved external "foo"`), which the official linker of the mod tools does not report at compile time.

The order was measured by running the game's own script loader (`gruff-data/semantics/t7.toml`: `bare_call_using_file_other_namespace`, `bare_call_using_file_shadows_builtin`, `func_ref_builtin_only`). On the 973 mod-tools scripts of Black Ops III, which the official linker builds and the game loads, the rule reports nothing. In the retail bytecode of Black Ops 4 and Cold War, no get-call import (what a bare call or `&f` compiles to) names another namespace (`gruff-data/evidence/bytecode/t8-import-namespaces.tsv`, `t9-import-namespaces.tsv`).

Resolution, go-to-definition and completion in the language server follow the same order: such a call has no definition, and a bare-name completion does not offer the functions of other namespaces.

## Example

```gsc
#using scripts\shared\util_shared;

#namespace mymod;

function main()
{
    wait_network_frame();        // B004 a bare call to `wait_network_frame` resolves in namespace `mymod`, then the builtins, never in another namespace: `wait_network_frame` is defined in namespace `util` (scripts/shared/util_shared.gsc); write `util::wait_network_frame`
    util::wait_network_frame();  // fine
    f = &spawnstruct;            // fine: no script function `mymod::spawnstruct`, so the builtin
}
```

## Fix

When the functions found are all in one namespace, an **unsafe** fix inserts the qualifier (`--fix --unsafe-fixes`). It is unsafe because the function found may be private, or in a file the script does not `#using`.

## How to suppress

On the line (or on its own line just above it):

```gsc
wait_network_frame();  // gsc: ignore[B004]
```

For a whole file, anywhere in it: `// gsc: ignore-file[B004]`. In `gruff.toml`:
`ignore = ["B004"]`, or `[check.per-file-ignores]` with `"pattern" = ["B004"]`.

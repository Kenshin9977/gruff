# U002 uninitialized-variable

**Preview**: off unless `--preview` (or `preview = true`).

## What it does

Reports the first read of a local that nothing in its function assigns: not a parameter, `foreach` binding, `waittill` output, `const`, file constant, global object, nor a name a used macro's body holds. A `vararg` read in a function without `...` gets its own message. Order is ignored: a write anywhere in the function counts. Class methods, decompiler output, upper-case names (macros) and files with an `#insert` the workspace cannot find are skipped.

## Why

The value is undefined, usually a typo or a variable renamed in one place. The BO3 compiler refuses it: "Uninitialized local variable" (`lint_uninit_local.gsc`; it also refuses a read that comes before the only write in source order, `lint_uninit_local_later.gsc`, which this rule does not report). The IW compilers accept it, which keeps it in preview. After gscode's `UnassignedVariableLint` and `VarargOutsideVarargFunction` (GPL-3.0).

Measured: 35 findings in the shipped sources (CoD1 30, WaW 2, CoD4, MW2, BO1 1 each), all real; most are CoD1's deliberate `homemade_error = crap_out_now + please;`.

## Example

```gsc
function f()
{
    view.angles = angle;  // U002: angles was meant
}
```

## How to suppress

On the line (or on its own line just above it):

```gsc
x = y;  // gsc: ignore[U002]
```

For a whole file, anywhere in it: `// gsc: ignore-file[U002]`. In `gruff.toml`:
`ignore = ["U002"]`, or `[check.per-file-ignores]` with `"pattern" = ["U002"]`.

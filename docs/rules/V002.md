# V002 thread-call-value

**Preview**: off unless `--preview` (or `preview = true`).

## What it does

Reports the value of a `thread` call used for something (assigned, passed, tested, returned) when the started function may wait, in games whose profile says `thread_call_value = "callee-result"` (CoD4, WaW, BO1, BO2, BO3, BO4, measured in their VMs). Silent in Cold War (`finalization`: the value is a thread value of its own) and where the profile says `unknown`.

## Why

A threaded call gives its caller the function's return value only if the function ends before its first wait; once it waits the caller gets undefined (gruff-data `semantics/<game>.toml`, `thread_call_assign_result`). A function that never waits is not reported: its value is right, if fragile. After gscode's `ConsumedThreadedCallResult` (GPL-3.0).

Measured: 61 findings in the shipped sources (BO3 13, WaW 40...) and 55 in decompiler output.

## Example

```gsc
self.fx[ self.fx.size ] = self thread burn_stage( tags );  // V002: burn_stage waits
```

## How to suppress

On the line (or on its own line just above it):

```gsc
x = thread f();  // gsc: ignore[V002]
```

For a whole file, anywhere in it: `// gsc: ignore-file[V002]`. In `gruff.toml`:
`ignore = ["V002"]`, or `[check.per-file-ignores]` with `"pattern" = ["V002"]`.

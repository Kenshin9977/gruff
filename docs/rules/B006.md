# B006 builtin-shadowed-function

## What it does

Reports a script function named like a builtin of the file's game mode and VM in a `builtin-strict` game (Black Ops II), when bare calls that would otherwise reach it link to the builtin instead: calls in its own file, and calls in the files whose first `#include`d definition of the name is this one. A builtin function shadows plain calls `foo()`, a builtin method shadows method calls `ent foo()`; when only one kind of builtin exists and the function is also called in the other form somewhere, the shadowed calls are taken to mean the builtin and nothing is reported.

The builtins are those of the file's game mode (see [Game modes](../modes.md)): Black Ops II ships one executable per mode, and a campaign script may define `spawnfx` or `playloopedfx` because only the multiplayer and zombies executables have those builtins. The rule needs a catalogue that is complete for the file's mode, and is preview.

## Why

The Black Ops II linker looks a bare call up among the builtins of the call's kind before any script function, even one of the same file (measured in the game's VM: `gruff-data/semantics/t6.toml`, `bare_call_resolution = "builtin-strict"`). The function is then dead for those calls: they run the builtin, whatever the function does. Only a path-qualified call (`maps\mp\_utility::foo()`) or a threaded one (`thread foo()`, which never links to a builtin) reaches it. Renaming the function, or qualifying the calls, makes the intent explicit.

On the game's own scripts (3,864 decompiled files) the rule reports 10 functions, among them `array` in `clientscripts/mp/_utility.csc` (37 calls of the files that include it run the builtin `array`) and `addspawnpoints` in `maps/mp/gametypes/_spawnlogic.gsc` (the game itself calls it path-qualified from the game types).

## Example

```gsc
#include maps\mp\_utility;

vectorcross( a, b )        // B006: `vectorcross` is also a builtin function
{
    return ( a[1] * b[2] - a[2] * b[1], a[2] * b[0] - a[0] * b[2], a[0] * b[1] - a[1] * b[0] );
}

f( a, b )
{
    c = vectorcross( a, b );   // runs the builtin
    d = maps\mp\gametypes\_weaponobjects::vectorcross( a, b );  // runs the function above
}
```

## How to suppress

On the line (or on its own line just above it):

```gsc
vectorcross( a, b )  // gsc: ignore[B006]
```

For a whole file, anywhere in it: `// gsc: ignore-file[B006]`. In `gruff.toml`:
`ignore = ["B006"]`, or `[check.per-file-ignores]` with `"pattern" = ["B006"]`.

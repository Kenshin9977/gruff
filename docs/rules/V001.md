# V001 hash-equality

**Preview**: off unless `--preview` (or `preview = true`).

## What it does

Reports `==` with a hash literal (`#"name"`) on either side, in a game whose profile says
`hash_equality = "script-error"`: Black Ops III.

## Why

Measured in the emulated BO3 VM (`gruff-data/semantics/t7.toml`, behaviour `hash_equality`):
`==` between two hashes, or between a string and a hash, is a script error (`pair 'hash' and
'hash' has unmatching types`) and the result is false, even for `#"goaway" == #"goaway"`. The
thread goes on, so the comparison silently never matches. Black Ops 4 and Cold War compare
hashes by value (`#"GoAway" == #"goaway"` and `"goaway" == #"goaway"` are true there), which is
what code ported from them expects.

Only `==` was run in the VM; `!=` and `===` are not reported.

## Why it is in preview

The BO3 mod tools scripts and the decompiled BO3 scripts hold no such comparison: the rule has
nothing to be measured on yet.

## Example

```gsc
function on_notify( name )
{
    if ( name == #"spawned" )   // V001: always false in BO3, and a script error
    {
        self thread setup();
    }
}
```

## How to suppress

`// gsc: ignore[V001]` on the line.

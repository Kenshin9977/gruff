# L002 unreachable-code

**Preview**: off unless `--preview` (or `preview = true`).

## What it does

Reports the statements that follow a `return`, `break` or `continue` in the same block, as one range.

Not reported: a lone `break` after a `return` (a habit, not a mistake); code after the jump when an `#if`/`#else` line separates them (another configuration may compile the jump out); code inside a `/# #/` dev block; decompiler output.

## Why

The code never runs; it is usually a debugging `return;` left in. The BO3 linker accepts it (`lint_unreachable.gsc`). After gscode's `UnreachableCodeLint` (GPL-3.0).

Measured: 70 findings in the shipped sources (BO3 5, BO1 19, CoD1 29...), every one sampled a real dead block.

## Example

```gsc
function f()
{
    return;
    self thread watch();  // L002
}
```

## How to suppress

On the line (or on its own line just above it):

```gsc
return;  // gsc: ignore[L002]
```

For a whole file, anywhere in it: `// gsc: ignore-file[L002]`. In `gruff.toml`:
`ignore = ["L002"]`, or `[check.per-file-ignores]` with `"pattern" = ["L002"]`.

# B002 builtin-arg-count

## What it does

Reports a call to a builtin with fewer or more arguments than the engine accepts (the `min_args`/`max_args` of the catalogue, measured in the executable). Function versus method is decided by the call shape and the VM by the file extension. Builtins whose arity the engine does not record are skipped, and so are entries marked `arity_unknown` (the extraction's measure was contradicted by the game's own scripts). When the engine ignores extra arguments (`max_checked = false`, most IW builtins) only too few arguments are reported. Intrinsics are checked against the arity of their `[[intrinsic]]` entry, when it gives one. A call a script function of the same name could receive is skipped too, in the order of the profile's `bare_call_resolution`: one in the same file, in the same namespace, or in a `#using`/`#include`d file; only one of the same file in `file-first` games (an `#include`d function does not shadow a builtin there), and none in `builtin-strict` games (Black Ops II: the builtin comes first even when the file defines the name). Threaded calls are skipped in `file-first` and `builtin-strict` games, which never link them to a builtin ([B005](B005.md)).

## Why

The VM checks builtin arity at run time and stops the script with an error (Treyarch T6 and later check it when the script is linked).

## Example

```gsc
function f()
{
    x = randomint();       // B002 builtin function `randomint` takes 1 argument, but 0 were given
    y = randomint( 10 );   // fine
}
```

## How to suppress

On the line (or on its own line just above it):

```gsc
x = randomint();  // gsc: ignore[B002]
```

For a whole file, anywhere in it: `// gsc: ignore-file[B002]`. In `gruff.toml`:
`ignore = ["B002"]`, or `[check.per-file-ignores]` with `"pattern" = ["B002"]`.

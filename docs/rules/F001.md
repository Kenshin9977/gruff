# F001 unknown-field

**Preview**: off unless `--preview` (or `preview = true`).

## What it does

Reports a field read (`self.helath`) whose name the engine does not register on any object kind (`gruff-data/fields/<game>.toml`, matched by hash), that no script of the workspace sets (`x.f = ...`, `x.f++`, a struct literal key, a `foreach` binding) or tests (`isdefined( x.f )`, `IS_TRUE( x.f )`), and that is one typo away from a name that is: same length, one letter changed or two adjacent letters swapped. It suggests the near name.

Names that differ only by an underscore, by a trailing number (`origin1`/`origin2`) or by an axis letter (`offset_x`/`offset_y`) are naming variants, not typos, and are never reported. Neither are names starting with `script_` (map key-value pairs), hashed names, and names under five letters. Without a field catalogue for the game the rule is silent.

A typo is a slip in one place, so a name that three or more files read and none of them writes is not reported either: it is a field set outside the scripts, a map key-value pair or a GDT or script-bundle key (`struct::get_script_bundle` hands those back as fields). That one test is what the rule's false reports all were: on the Black Ops III mod-tools source it reported `vmtype`, a scene bundle key, eleven times across six files, and nothing else; with the test it reports nothing there. On the decompiled corpus it goes from 14 findings to 3 (`ddbomb` twice, `ksvehicle` once).

## Why

Reading a field nobody writes yields `undefined`, silently: the condition is never true, the value never arrives.

The rule is in preview because fields are also set outside scripts: map key-value pairs and GDT or script-bundle keys (`struct::get_script_bundle` returns them as fields). The test on how many files read a name covers the ones that are read widely; a key read in one or two files would still be reported, and a catalogue of asset keys is what would settle it. Nothing yet says how often that happens, since the corpora are shipped scripts, where a typo is rare by construction: the rule has no measured true report, only three candidates on decompiled output.

## Example

```gsc
function f()
{
    self.counter = 0;
    if ( self.helath < 50 ) { }   // F001 did you mean `health`?
    y = self.coutner;             // F001 did you mean `counter`?
}
```

## Fix

When there is exactly one candidate, an **unsafe** fix renames the field (`--fix --unsafe-fixes`).

## How to suppress

On the line (or on its own line just above it):

```gsc
if ( self.helath < 50 ) { }  // gsc: ignore[F001]
```

For a whole file, anywhere in it: `// gsc: ignore-file[F001]`. In `gruff.toml`:
`ignore = ["F001"]`, or `[check.per-file-ignores]` with `"pattern" = ["F001"]`.

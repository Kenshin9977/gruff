# T003 waittill-arg-count

**Preview**: off unless `--preview` (or `preview = true`).

## What it does

What `waittill` does with the notify's values depends on the game (gruff-data profile features `waittill_return_value` and `waittill_multiple_events`, measured in the emulated BO3, BO4 and Cold War VMs, `gruff-data/semantics/`). Black Ops III and earlier bind them to the names after the event; Black Ops 4 and later bind nothing: `waittill` returns a struct holding the fields of the notify's payload struct and `_notify`, every argument is an event, and plain values after a notify's event are dropped.

**Games that bind names** (`waittill_return_value = false`). Reports a `waittill( "e", a, b, c )` that binds more variables than any notify of `"e"` sends. It applies only when the evidence is complete:

- at least one script notifies `"e"` with the `notify` keyword, and every script notify of it does (a wrapper such as `delay_notify` sends an unknown payload: no report);
- no notify with a dynamic name (`self notify( msg, x, y )`) sends as many values anywhere in the workspace;
- when the engine catalogue lists `"e"`, its payload counts too, and a variable payload (`args_variable`) silences the rule;
- without a complete engine catalogue, the engine may notify the event too (scripts re-notify engine events such as `"damage"` with part of the payload): the rule then reports only a lone waiter, never an event that several `waittill`s bind past the scripts' payload;
- the bound arguments are plain names, and the `waittill` result is not assigned (`r = self waittill( "a", "b", x )` in BO4 and later takes every argument as an event name).

The report covers the variables that are always `undefined`.

**Games whose `waittill` returns the payload struct** (`waittill_return_value = true`: BO4, Cold War, and BO6/BO7 assumed from them). Reports `r.f` after `r = self waittill( "e" )` (or `waittill( "a", "b" )`, whose result comes from either) when no notify sends a field `f`:

- every script notify of each event is the `notify` keyword with a struct literal payload (`{ #f: v }`) or none, so the fields it sends are known;
- the engine catalogue does not list the event (the engine's payload fields are not in it);
- a notify of a computed name (`self notify( msg, { ... } )`) counts for an event whose name is written as a string elsewhere, and one sending another payload silences the rule for such events;
- the read is in the block of the `waittill` and before `r` is assigned again (a read after an `if` whose branches wait for different events is not judged); `_notify` and fields the function writes into `r` are never reported.

## Why it is in preview

Measured on the local corpus of 20 games without engine catalogues: 4 reports in all (MW2019 1, WWII 3). One is a stale binding (`"returned"`, 9 variables for at most 7 values); the three WWII ones are engine events the scripts also notify (`"death"`, `"foley"`, `"supplydrop"`). Without the lone-waiter filter, BO3 alone gave 65 reports, all the engine's `"damage"` (10 values, re-notified by scripts with 9).

Measured again with the 13 engine catalogues (2026-11-06): the same 4 reports, since WWII and MW2019 have no catalogue yet; the 13 catalogued games give none. Read as complete, the catalogues would lift the lone-waiter filter and add 4 false reports on Ghosts (`"flashbang"`: the catalogue's payload, 5 values, is shorter than what the scripts bind). One true report in four: **it stays in preview** until the catalogues' payloads are checked against the waits (the WWII and MW2019 catalogues would also remove the three false ones).

Measured on 2026-11-06 with the T8/T9 semantics: 0 reports on the decompiled BO4 and Cold War scripts (one wait per game passes every condition, and its reads are sent), the BO3 and other games unchanged (the same 4 reports). The retail scripts rarely give a known payload: most waited events come from the engine or from notifies whose payload is a variable.

## Why

The variables past the notifier's payload are always `undefined`. It is usually a stale `waittill` left behind after the `notify` changed, or a wait on the wrong event.

## Example

```gsc
function a()
{
    self notify( "picked_up", self.item );
}

function b()
{
    self waittill( "picked_up", item, player );   // T003: `player` is always undefined
}
```

```gsc
// Black Ops 4 and later
function a()
{
    self notify( "picked_up", { #item: self.item } );
}

function b()
{
    s = self waittill( "picked_up" );
    item = s.item;
    who = s.player;   // T003: no notify of "picked_up" sends `player`
}
```

## How to suppress

`// gsc: ignore[T003]` on the line.

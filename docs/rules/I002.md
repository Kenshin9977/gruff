# I002 unused-import

**Preview**: off unless `--preview` (or `preview = true`).

## What it does

Reports a `#using` or `#include` whose file supplies nothing the script uses.

An import counts as used, and is never reported, when any of these holds:

- a call, function reference, class (`new`, `class x : y`) or qualifier of the file names a function, class or namespace the imported file declares; for `#include` (CoD4 to Black Ops II and the IW games), the files that file includes count too, since `#include` merges them;
- a name in the body of a macro the file sees (its own `#define`s and those of the headers it `#insert`s) does;
- the imported file, or anything it imports in turn, does something when it is loaded: an `autoexec`, `codecall` or `event_handler` function, or a file-scope macro call such as `REGISTER_SYSTEM`.

Nothing is reported in a file with an `#insert` the workspace cannot find, or with a call resolution could not place (either could be the missing use), nor in decompiler output.

## Why

A stale import slows linking and misleads readers about what a script depends on. After gscode's `UnusedUsingLint` and `UnusedIncludeLint` (GPL-3.0).

Measured: 1,312 findings on the shipped sources of the local corpus (BO3 mod tools 104, BO1 806, WaW 238, CoD4 95, MW2 63); a cross-check of every one against the imported file's functions found no import that was in fact used.

## Example

```gsc
#using scripts\shared\weapons\_weapon_utils;  // I002: its only call is commented out
```

## Fix

A **safe** fix deletes the directive with its line (`--fix`): the import has no load effect and nothing it declares is named.

## How to suppress

On the line (or on its own line just above it):

```gsc
#using scripts\shared\array_shared;  // gsc: ignore[I002]
```

For a whole file, anywhere in it: `// gsc: ignore-file[I002]`. In `gruff.toml`:
`ignore = ["I002"]`, or `[check.per-file-ignores]` with `"pattern" = ["I002"]`.

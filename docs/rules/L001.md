# L001 infinite-loop-without-wait

## What it does

Reports `while ( 1 )`, `while ( true )`, `for ( ;; )` and `do { } while ( 1 )` loops whose body never waits: no `wait`, `waitrealtime`, `waitframe`, `waittillframeend`, `waittill`, `waittillmatch`, and no synchronous call to a function that may wait.

"May wait" is computed for every function of the workspace with a fixpoint over the call graph. Calls started with `thread` or `childthread` do not count: they do not suspend the caller. A call to an unknown function, through a pointer, or to a macro whose body is unknown counts as waiting, so the rule stays silent rather than guess. Builtins never wait. A loop whose body contains `break`, `return` or `goto` anywhere is never reported.

## Why

A script thread runs until it waits. A loop that never waits freezes the server, and the VM kills it with "potential infinite loop in script".

## Example

```gsc
function watch()
{
    while ( 1 )   // L001
    {
        self.health = 100;
    }
}

function watch_ok()
{
    while ( 1 )
    {
        self waittill( "damage" );
        self.health = 100;
    }
}
```

## Fix

An **unsafe** fix appends `wait 0.05;` to the loop body (`--fix --unsafe-fixes`). It changes timing, so review it.

## How to suppress

On the line (or on its own line just above it):

```gsc
while ( 1 )  // gsc: ignore[L001]
```

For a whole file, anywhere in it: `// gsc: ignore-file[L001]`. In `gruff.toml`:
`ignore = ["L001"]`, or `[check.per-file-ignores]` with `"pattern" = ["L001"]`.

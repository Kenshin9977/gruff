# T001 unknown-event

**Preview**: off unless `--preview` (or `preview = true`).

## What it does

Reports a `waittill`, `waittillmatch` or `endon` (or a wrapper such as `waittill_any`, `waittill_any_timeout` or `wait_endon`) on a literal event name that nothing can notify:

- no script of the workspace notifies it, literally (`notify( "x" )`, `delay_notify( "x" )`) or through a pattern (`notify( "trigger_" + n )` counts for every `trigger_*` name);
- the string is not used anywhere else in the scripts either (passed to a helper, stored in a field, compared): such a string may reach a `notify( var )`;
- the engine's event catalogue (`gruff-data/events/<game>.toml`) does not list it;
- fewer than three files wait for it or end on it: a name many files wait for and nothing visible notifies is someone's event (the engine's, a map's, a menu's), not a typo.

When a known event is one or two edits away, on a compatible receiver, the message suggests it.

Names are compared without case. Dynamic names (`waittill( msg )`) and hashed spellings (`hash_1a2b3c4d`) are never judged.

**The rule needs a complete engine catalogue.** Without `gruff-data/events/<game>.toml`, or when its `[coverage]` table does not say `complete = true`, every engine event (`death`, `damage`, `trigger`, `movedone`...) would look unknown: the rule is then silent. [T002](T002.md) covers the typo case without the catalogue.

## Why it is in preview

On the local corpus of 20 games, without an engine catalogue, the waits no script explains (what T001 would report with a complete but empty catalogue) number 87 sites on BO3's dump, 57 on its mod-tools source, 477 on BO2, 485 on BO1 and 603 on the MWIII campaign. Most are engine events, but many are notified from data no script holds: animation notetracks (`"fireball"`, `"orientdone"`), map key-value pairs (`script_notify`), menus and client-field callbacks.

Measured again with the 13 engine catalogues of phase 3 (2026-11-06; IW3-IW7, S1, H1, T4-T9; none says `complete = true`, so T001 is silent on every game): read as if they were complete, they would leave 2,921 reports on 1,482 distinct names (T5 532, T6 435, T4 369, S1 357, IW6 314, IW5 241, IW4 186, H1 176, IW3 121, BO3 100, IW7 81, T9 5, T8 4). The most frequent are script events notified through variables or helpers the rule cannot follow (`"_stealth_stop_stealth_logic"`, `"xenon_auto_aim_stop_logic"`), effect-editor messages (`"effect id changed"`) and animation events (`"animsdone"`). The rule stays gated on `[coverage] complete = true`: a catalogue of `Scr_Notify` calls cannot list those names.

## Why

A `waittill` on an event nobody notifies blocks its thread forever; an `endon` on one never ends the thread, so the clean-up it was written for never happens (`self endon( "dissconnect" )`).

## Example

```gsc
function watch()
{
    self endon( "dissconnect" );   // T001 ... did you mean "disconnect"?
    self waittill( "spawned_playr" );   // T001 ... did you mean "spawned_player"?
}
```

## How to suppress

On the line (or on its own line just above it): `// gsc: ignore[T001]`. Events notified from outside the scripts (menus, map entities, client scripts that the workspace does not hold) are the usual reason; add the scripts that notify them as a library root (`--library`) instead when you can.
